## Decision

`python-rsa` is suitable for AsynCodeBench v0.3 after manual dependency
review. The original automatic screening marked it `weak_or_unclear` because
the raw environment lacked `pyasn1` and the upstream pytest configuration
required coverage plugins. Both are environment/configuration issues, not
task-structure blockers.

After installing the runtime dependency declared in `pyproject.toml`
(`pyasn1`) and disabling upstream addopts with `-o addopts=`, the complete
reference branch passes the scoped evaluator, while the stripped Commit0-style
ref fails with substantive implementation gaps.

1. `arithmetic_and_codec_core`

   - `rsa/key.py`
3. `serialization_contracts`
   - `rsa/asn1.py`
   - `rsa/pem.py`
4. `pkcs1_crypto_api`
   - `rsa/pkcs1.py`

Primary dependency labels:

- `python_rsa.arithmetic_to_key_generation.inverse_prime_contract`
- `python_rsa.key_to_serialization.pem_der_contract`
- `python_rsa.codec_key_to_pkcs1.crypto_api_contract`

This is a strong async task because downstream workers can plausibly implement
key serialization or PKCS#1 behavior against stale assumptions about arithmetic,
byte sizing, key field layout, or DER/PEM return types. These errors are
semantic integration failures, not just textual merge conflicts.
